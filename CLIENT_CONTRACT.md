# Контракт браузерного клиента

Реализованный сценарий блока сохранения/API. Полные договорённости: [FRONTEND_FLOW.md](FRONTEND_FLOW.md). Детали HTTP: [README.md](README.md#http-контракт).

## Приём и запись

1. История открывается через `GET /api/requests`; новые приёмы сверху, cursor-пагинация.
2. «Начать новый приём» вызывает `POST /api/requests`, backend выдаёт `requestId`. При `409 ACTIVE_REQUEST_EXISTS` открывается существующий приём.
3. Одна запись на приём. Отдельных `recordingId` и `uploadId` нет.
4. Встроенный рекордер сохраняет чанки в IndexedDB примерно раз в секунду. Стоп дожидается последнего чанка, сохраняет часть и не отправляет HTTP. Продолжение создаёт следующую часть.
5. «Завершить приём» сохраняет локальный запрет дозаписи, останавливает микрофон и дожидается последнего чанка. Запрет переживает ошибку и перезагрузку; устаревший серверный `created` его не снимает.
6. Все части отправляются одним multipart-запросом `/complete`. Поле `manifest` задаёт порядок, размер, MIME и SHA-256. `partNo` нужен только для приёма/склейки; дальше обрабатывается единое аудио.

## Сохранение и ошибки

Успех `/complete` означает сохранение S3 и закрытие в PostgreSQL. `202` означает продолжающуюся операцию и требует polling. Для выбора retry используются `error.code` и `error.retryAction`; при потере ответа сначала проверяется GET состояния.

- Нужны файлы → повтор неизменного multipart.
- S3 уже сохранён → повтор `/complete` с JSON `{}`.
- Исход неизвестен → повтор проверки состояния.
- Изменённые данные → конфликт, перезапись запрещена.

После ошибки доступно явное «Закрыть без сохранения» с подтверждением. Backend фиксирует `abandoned`, пользователь может начать следующий приём. Принудительное закрытие не отменяет уже успешно закрытый приём.

## Ожидание и документ

После закрытия открывается экран «Отчёт в обработке» с polling раз в 2 секунды без замены экрана. Следующий приём уже разрешён. Временный сбой polling сохраняет экран и повторяет запрос. SLO 30 секунд от сохранения до отчёта не является таймаутом.

При `completed` клиент получает `/report`: `{ requestId, format, schemaVersion, content }`. Сейчас формат — Markdown: очищенный от небезопасного HTML форматированный текст и скачивание `.md`. Переход на JSON предусмотрен отдельным обработчиком формата.

**Worker ещё не реализован**: этот блок регистрирует намерение обработки в PostgreSQL; автоматически готовые отчёты пока не появляются.

## Локальная сохранность

- Один браузерный захват на приём защищён Web Locks.
- Ошибки IndexedDB/квоты показываются и не считаются успешной записью.
- `audioStored: true` позволяет удалить чанки, сохранив метаданные приёма.
- После `abandoned` без S3 аудио хранится 3 часа от закрытия; затем очищается при работе приложения или следующем открытии.
- Активная запись не удаляется по TTL принудительного закрытия. При недоступном сервере локальная фиксация сохраняется.
- Существующие данные старого `overtone-recordings` не удаляются: при обновлении добавляются новые stores, старое аудио доступно для скачивания.
- Persistent storage запрашивается; ручная очистка данных браузера всё равно может удалить аудио.

До авторизации все браузеры используют одного технического пользователя. Свободной регистрации нет. Поддержка записей произвольной длительности ограничивается доступным диском/квотой и явно настраиваемыми техническими лимитами HTTP, а не длительностью приёма.
